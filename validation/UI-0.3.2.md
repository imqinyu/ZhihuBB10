# 0.3.2 双字段 Cookie、手机号登录与空状态

2026-10-27，Cascades 1.4 / Qt 4.8，原生模拟器 192.168.106.129。

## 实现

- Cookie 登录分别输入 z_c0 与 d_c0，可粘贴原值或 name=value，完整 Cookie 自动提取两项。
  保留值中的等号和竖线，拒绝控制字符、分号注入和超长值。验证失败不覆盖已有账号。
  页面说明改为从浏览器 Application / Cookies 取得值，避免 document.cookie 读不到 HttpOnly z_c0。
- 手机号登录移植本地 Zhihu++ 的设备预热、访客初始化、加密表单、HMAC 签名、短信、
  图形验证码和登录分支。60 秒重发倒计时；20 秒请求超时；HTTPS 保留证书和主机名校验。
  接口返回凭据后仍通过 /me 验证才保存；手机号和验证码不写设置或日志。
  移动 token 仅存于私有账号设置，账号列表、当前资料和剪贴板复制不暴露 token 字段。
- EmptyState 参照 BB10 UI Guidelines p.114，使用灰色图标、标题、说明和单个引导按钮。
  按实际视口居中，小屏可滚动。覆盖主要内容列表、历史／收藏、搜索、账号和评论。
  请求失败有重试，未登录有登录入口；有缓存内容时保留列表并显示错误提示。
- 搜索未提交时只显示搜索引导；从历史／收藏返回首页逐页执行原生 pop 并释放页面。

## 验证

- ARM 与 x86 构建和 BAR 打包通过，正式版本 0.3.2。
- 隔离 QA 应用中验证两项粘贴、完整 Cookie 提取、等号／竖线保留、非法输入不发验证、
  复制／删除账号和凭据字段隐藏；不使用用户实际手机号，不发送短信。
- 原生 C++ 加密结果对照 Kotlin 算法生成的四组向量（空串、图形验证码、整块、短信表单），
  HMAC-SHA1 对照标准向量；手机号规范化和无效验证码检查通过。
- 原生加载登录分段、搜索引导、历史空状态及按钮跳转；检查深浅主题截图。
  视觉检查发现并修复了无搜索数据时的结果区显示，以及返回首页的页面销毁错误。
  最终 corrected-empty-0.3.2.log、corrected-login-0.3.2.log 中相关检查全部通过，
  无新增 ReferenceError、TypeError、缺失属性或绑定循环。
- 截图通过 QA 应用的 screen_read_window 读取自身窗口（768×1280），没有模拟网络内容，
  也没有把截图逻辑打入正式应用。记录在 ui-check/*0.3.2.log，图片在 shots/*0.3.2.png。
- 静态脚本有三项生产例外：已核实的 Carousel StackListLayout.orientation，以及原网络层
  和新增手机号协议的 HTTPS。用户要求直连 HTTPS，未关闭证书校验。其余扫描项来自历史验证目录。

## 验证边界

按用户要求没有验证线上手机号登录有效性，短信、服务端风控、图形验证码提交和 token 返回
仍需实际账号联调。www.zhihu.com 的设备预热可能受 BB10 证书／TLS 能力影响，错误会明确显示，
